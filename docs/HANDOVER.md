# Передача проекта «Модуль Эстет»

Сайт кухонь и шкафов на заказ: https://module-estet.ru. Документ для того,
кто принимает проект: где что лежит, как выкатывать, какие сервисы
подключены, что сделано и что осталось.

Секретов здесь нет и быть не должно: пароли и токены живут только
в `.env.local` на сервере. Ниже — названия переменных и зачем они нужны.

Моушн-дизайн (анимации, сцены, инструменты записи видео) описан отдельно:
[MOTION.md](./MOTION.md).

SEO — что сделано и что нужно от владельца (адрес, Яндекс Бизнес, Вебмастер):
[SEO.md](./SEO.md).

## 1. Коротко о проекте

| | |
|---|---|
| Стек | Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript |
| Пакетный менеджер | pnpm 10 (`packageManager` в `package.json`) |
| База данных | Postgres (Neon), драйвер `@neondatabase/serverless` |
| Файлы | Папка на сервере `STORAGE_DIR` (`/var/www/storage`, `lib/storage.ts`): заявки, планировки, фото квартир, портфолио, каталог. Neon Object Storage и Vercel Blob — для старых файлов, если доступны |
| Уведомления | Бот в мессенджере MAX |
| Аналитика | Яндекс.Метрика, счётчик **113551158** |
| Хостинг | Собственный облачный сервер Beget (не Vercel) |
| Репозиторий | `goavitomail-boop/module-estet`, рабочая ветка `claude/ecstatic-pasteur-gr53pi` |
| Знак и иконки | `components/module-estet-mark.tsx` — знак из шапки, им же пользуется панель; фавикон и иконки приложения собирает `node scripts/gen-icons.mjs` |

Сайт запускается командой `next start` после `next build` (`pnpm build`,
`pnpm start`). Конфиг Next — `next.config.mjs`.

## 2. Выкатка на сервер

Сайт лежит в `/var/www/html`. Рядом — `/var/www/html-old`: в неё собирается
новая версия, пока старая продолжает работать. Затем папки меняются местами.

### Одной командой (основной способ)

Скрипт `scripts/deploy.sh` делает всё, что описано в ручном порядке ниже:
скачивает свежий код ветки с GitHub в `html-old`, копирует `.env.local`,
ставит зависимости, собирает, меняет папки местами, перезапускает pm2 и
проверяет, что сайт отвечает. Упала сборка — останавливается, рабочий сайт
не тронут.

Установить на сервер — один раз (нужен git: `git --version`, если нет —
`apt install -y git`). Сначала скачать и прочитать, потом поставить:
```bash
curl -fsSL https://raw.githubusercontent.com/goavitomail-boop/module-estet/refs/heads/claude/ecstatic-pasteur-gr53pi/scripts/deploy.sh -o /root/deploy-site.sh && less /root/deploy-site.sh
```
```bash
install -m 755 /root/deploy-site.sh /usr/local/bin/deploy-site && rm /root/deploy-site.sh
```

Выкатить — скрипт покажет, какие коммиты и от кого уйдут на сайт, и спросит
подтверждение (`deploy-site --yes` — без вопроса):
```bash
deploy-site
```

Вернуть прошлую версию:
```bash
deploy-site --rollback
```

- Первый раз скрипт удаляет `html-old` и клонирует туда репозиторий; со
  второго раза только скачивает изменения — быстрее.
- Пуш в ветку сам по себе ничего не выкатывает: сайт меняется, только когда
  на сервере запустили `deploy-site`.
- Скрипт обновляет сам себя из репозитория после каждой выкатки.
- Другая ветка: `BRANCH=имя-ветки deploy-site`.

### Безопасность выкатки

- **Снаружи скрипт не запустить.** Он не слушает сеть, на сайте и в панели
  нет кнопки «обновить»: выкатить может только тот, кто уже вошёл на сервер
  по SSH. Поэтому кнопку выкатки в панель и не добавляли — она открыла бы
  путь с сайта на сервер.
- **Главный ключ — аккаунт GitHub.** Скрипт собирает и запускает код из ветки,
  значит, кто может писать в репозиторий, тот при следующей выкатке выполнит
  свой код на сервере. Закрыть: двухфакторный вход в аккаунт
  `goavitomail-boop`, в Settings → Collaborators — никого лишнего, в
  Settings → Rules — запрет force-push в рабочую ветку. Перед выкаткой
  скрипт показывает список коммитов с авторами: незнакомый — не подтверждать.
- **Публичный репозиторий читают все,** но паролей в нём нет — они только
  в `.env.local` на сервере. Сделать репозиторий приватным можно: тогда
  серверу нужен ключ развёртывания только на чтение (Settings → Deploy keys)
  и `REPO_URL=git@github.com:goavitomail-boop/module-estet.git`.
- **Зависимости.** Версии и контрольные суммы закреплены в `pnpm-lock.yaml`
  (`--frozen-lockfile`), а pnpm 10 не запускает установочные скрипты пакетов.
- **Сервер.** Вход по SSH — только по ключу, пароль root отключить
  (`PasswordAuthentication no`). Лучше, чтобы сайт и сборка работали
  не от root, а от отдельного пользователя: тогда даже вредный пакет
  не получит весь сервер.
- Скрипт обновляет сам себя из репозитория — это та же граница доверия,
  что и код сайта, отдельного риска не добавляет. `.env.local` копируется
  с теми же правами (`cp -p`), замок выкатки лежит в `/var/www`, а не в `/tmp`.

### Вручную (запасной способ)

1. **Скачать код ветки** архивом:
   `https://github.com/goavitomail-boop/module-estet/archive/refs/heads/claude/ecstatic-pasteur-gr53pi.zip`.
   Внутри одна папка — закидывать её **содержимое**.
2. **Очистить `/var/www/html-old`** и распаковать туда файлы.
3. **Скопировать `.env.local`** из `/var/www/html` в `/var/www/html-old`.
   В архиве этого файла нет. Без него сайт соберётся, но заявки, админка
   и уведомления работать не будут.
4. **Собрать** (по SSH), старый сайт в это время работает:
   ```bash
   cd /var/www/html-old
   pnpm install
   pnpm build
   ```
   Ошибка в конце вывода — дальше не идти: рабочий сайт не затронут.
5. **Поменять папки местами:**
   ```bash
   cd /var/www
   mv html html-tmp && mv html-old html && mv html-tmp html-old
   ```
6. **Перезапустить сайт.** Он работает под pm2, процесс `nextjs-app`:
   ```bash
   pm2 restart nextjs-app
   pm2 save
   ```
   Список процессов и их состояние — `pm2 list`, журнал сайта — `pm2 logs nextjs-app`.
7. **Проверить** главную, `/quiz`, `/admin`.

### Откат

Повторить шаг 5 (папки снова поменяются) и перезапустить. Предыдущая
версия лежит в `html-old` до следующей выкатки.

### Локально

- Windows: `start-local.bat` — ставит зависимости, собирает и запускает.
- Любая система: `pnpm install`, затем `pnpm dev` (разработка) или
  `pnpm build && pnpm start`. Сайт на http://localhost:3000.
- Без `.env.local` сайт открывается, но заявки не принимаются: их некуда
  сохранить и некому отправить, поэтому формы показывают ошибку с телефоном.
  Так же сайт ведёт себя на сервере, если одновременно недоступны база и MAX.

## 3. Переменные окружения

Файл `.env.local` в корне проекта, на сервере — в `/var/www/html`. Образец
с подробными пояснениями — `.env.example`. **Никогда не коммитить**
`.env.local` (он в `.gitignore`).

| Переменная | Зачем | Обязательна |
|---|---|---|
| `DATABASE_URL` | Postgres. Также читаются `POSTGRES_URL`, `DATABASE_URL_UNPOOLED`, `POSTGRES_URL_NON_POOLING` | да — без неё заявки не сохраняются |
| `STORAGE_DIR` | Папка для файлов сайта на этом сервере, вне `html` и `html-old`: `/var/www/storage`. Если задана — все новые файлы туда | нет — без неё файлы идут в Neon или Blob |
| `AWS_ENDPOINT_URL_S3`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` | Neon Object Storage — бакет `files` для всех файлов сайта. Ключ: `neon credentials create --scope storage:read --scope storage:write` на ветке production | да — без них файлы пишутся в Vercel Blob |
| `STORAGE_BUCKET`, `STORAGE_CORS_ORIGINS` | Другое имя бакета; ещё адреса для загрузки из браузера (сайт и www разрешены всегда) | нет |
| `BLOB_READ_WRITE_TOKEN` | Старое хранилище Vercel Blob: читать файлы, ещё не перенесённые в Neon | пока не выполнен перенос |
| `BLOB_STORE_ID` | Идентификатор хранилища Vercel Blob | по ситуации |
| `ADMIN_PASSWORD_HASH` | Пароль админки в виде `scrypt:соль:хеш`. Команда генерации — в `.env.example` | да |
| `ADMIN_PASSWORD` | Устаревший пароль открытым текстом. Панель помечает его как небезопасный | нет — лучше перейти на хеш |
| `ADMIN_SESSION_SECRET` | Подпись сессионной куки, 32+ случайных символа. Из него же выводится ключ кук личного кабинета | желательно |
| `CLIENT_SESSION_SECRET` | Свой ключ для кук личного кабинета вместо производного | нет |
| `SITE_URL` | Адрес сайта в ссылках, которые бот шлёт клиентам; по умолчанию https://module-estet.ru | нет |
| `MAX_BOT_USERNAME` | Имя бота для ссылки привязки MAX; без него берётся у бота запросом /me | нет |
| `MAX_BOT_TOKEN` | Токен бота MAX | да — для уведомлений |
| `MAX_NOTIFY_USER_ID` | Кому слать заявки. **Несколько получателей — через запятую**: `12345,67890` | да |
| `MAX_NOTIFY_CHAT_ID` | Групповой чат или канал для дубля заявок | нет |
| `MAX_WEBHOOK_SECRET` | Проверка входящих событий бота (`/api/max-webhook`) | желательно |
| `MAX_DIAG_KEY` | Ключ к диагностике `/api/max-diag` (без него — 404) | нет |
| `MAX_API_BASE`, `MAX_STRICT_TLS` | Адрес API MAX и строгая проверка TLS | нет |
| `CRON_SECRET` | Защита регулярных задач `/api/cron/*` | да, если задачи открыты в интернет |
| `MEASUREMENT_SLOT_CAPACITY` | Сколько замеров в один слот (утро/день/вечер), по умолчанию 1 | нет |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | Номер счётчика. По умолчанию 113551158 | нет |
| `NEXT_PUBLIC_MAX_CHAT_URL` | Ссылка «Написать в Max» | нет |
| `NEXT_PUBLIC_YANDEX_VERIFICATION`, `NEXT_PUBLIC_GOOGLE_VERIFICATION` | Подтверждение прав в вебмастерах (код Яндекса уже записан в `app/layout.tsx`, переменная его заменяет) | нет |

После изменения `.env.local` сайт нужно перезапустить. Переменные
`NEXT_PUBLIC_*` попадают в код при сборке — после их смены нужна пересборка.

## 4. Подключённые сервисы

### База и файлы
- Заявки, сессии квиза, замеры, каталог и портфолио — в Postgres
  (`lib/db.ts`).
- **Файлы — на самом сервере**, если в `.env.local` задан
  `STORAGE_DIR=/var/www/storage`. Загрузки из квиза и панели идут через
  сайт (`PUT /api/upload`, `PUT /admin/upload`) и ложатся в эту папку;
  посетителю картинки отдаёт `/media/...`, менеджеру файлы заявок —
  `/admin/file`. Состояние и свободное место — «Настройки» в панели.
  - nginx должен пропускать файлы до 25 МБ: `client_max_body_size 30m;` в
    блоке `server` сайта, иначе крупные файлы он отклонит сам (по умолчанию 1 МБ).
  - Папку нужно бэкапить вместе с сервером: копий в другом месте нет.
  - Выкатка (`deploy-site`) создаёт папку, если её нет, и остановится, если
    она по ошибке внутри папки сайта.
- Ниже — прежняя схема с Neon; она работает, если `STORAGE_DIR` не задан.
- Файлы — в приватном бакете `files` Neon Object Storage (`lib/storage.ts`,
  бакет объявлен в `neon.ts`). Посетителю фото портфолио и каталога отдаёт
  `/media/...` (там белый список папок), админке — `/admin/file`. Браузер
  грузит файлы прямо в бакет по подписанной ссылке, запасной путь — через
  сервер (`PUT /api/upload`, `PUT /admin/upload`).
- Vercel Blob — запасной: пока переменных `AWS_*` нет, файлы пишутся туда;
  когда есть, сайт читает сначала Neon, потом Blob, поэтому ещё не
  перенесённые файлы открываются.

### Запасные копии картинок

Фото, загруженные через панель, отдаёт маршрут `/media/…` из хранилища. Если
хранилище не отвечает (истёк ключ, поменялись права бакета), вместо них
серые заглушки. Для важных картинок есть копии в самом сайте:
`public/media-fallback/<папка>/<имя>.webp`, где имя — как в хранилище, но без
случайного суффикса (`catalog/l1-brash-chernyy-Og097….webp` →
`catalog/l1-brash-chernyy.webp`). Маршрут отдаёт копию, если хранилище упало
или файла там нет. Сейчас так сохранены 15 фото торцевых ручек L1–L3.

Фото фасадов и столешниц из панели (`catalog/facade-…`, `catalog/countertop-…`)
копий не требуют: маршрут сам находит те же картинки каталога в `public/catalog`
(список `ALIASES` в `app/media/[...path]/route.ts`).

В «Каталоге» панели блок «Есть в коде сайта, но нет здесь» показывает группы
из кода, которых нет в базе (например, «Корзины и колонны», «Подъёмники
TOP-STAYS SE»), — их можно добавить одной кнопкой. Фото у них лежат в сайте.

Причина отказа хранилища — в журнале сайта:
`pm2 logs nextjs-app --lines 500 --nostream | grep Медиа | tail -3`.

### Переезд файлов в Neon — один раз
1. Проверить регион проекта Neon: Object Storage есть в `aws-us-east-1`,
   `aws-us-east-2`, `aws-eu-central-1`, `aws-ap-southeast-1` (регион
   печатает проверка в GitHub Actions, задача «Neon — ветка базы»).
2. Создать бакет на production: `neon deploy` на ветке production (бакет
   объявлен в `neon.ts`) или в консоли Neon → ветка production → Object
   storage → New bucket `files`, доступ private.
3. Ключ для сервера: `neon credentials create --scope storage:read --scope storage:write --name module-estet-site`
   (на ветке production) или консоль → Settings → Credentials. Секрет
   показывается один раз — сразу в `.env.local` на сервере вместе с
   `AWS_ENDPOINT_URL_S3` и `AWS_REGION`. Никому не пересылать.
4. На сервере: `node --env-file=.env.local scripts/neon-storage.mjs setup` —
   CORS бакета (загрузка из браузера), затем перезапуск сайта.
5. Перенос старых файлов: `node --env-file=.env.local scripts/neon-storage.mjs migrate --dry-run`,
   потом без `--dry-run` (нужен ещё `BLOB_READ_WRITE_TOKEN`). Повторный
   запуск пропускает уже перенесённые. Проверка: `... neon-storage.mjs check`.
6. После переноса `BLOB_READ_WRITE_TOKEN` можно убрать, а хранилище Vercel
   Blob удалить не раньше, чем убедитесь, что старые заявки открываются.
7. Если перед сайтом nginx: `client_max_body_size 30m;` — иначе запасной
   путь загрузки через сервер отсечёт файлы больше 1 МБ.

### Бот MAX
- Новая заявка уходит всем из `MAX_NOTIFY_USER_ID` (`lib/max-bot.ts`,
  `lib/max-ui.ts`).
- В боте есть меню: списки заявок, фильтры, карточка заявки, статистика
  (`/api/max-webhook`).
- Настоящий `user_id` получателя виден только после того, как он открыл
  бота и написал ему. Узнать: `/api/max-diag?key=<MAX_DIAG_KEY>`, поле
  `incomingSenders`. Кто писал боту — также в `/admin/settings`.
- `/call?phone=...` — страница-переход на звонок из кнопки в MAX.

### Яндекс.Метрика
- Счётчик 113551158 (`lib/metrika.ts`, `components/yandex-metrika.tsx`).
- Загружается сразу. Если посетитель выбрал «только необходимые»
  cookie, счётчик выключается (`lib/consent.ts`).
- Цели, которые отправляет сайт. **Их нужно один раз завести в интерфейсе
  Метрики** («JavaScript-событие» с тем же идентификатором):

  | Идентификатор | Когда |
  |---|---|
  | `lead_measurement` | отправлена заявка на замер |
  | `lead_project` | отправлен квиз кухни |
  | `lead_wardrobe` | отправлен квиз шкафа |
  | `click_phone` | клик по номеру телефона |
  | `click_max` | клик по ссылке на MAX |

### Регулярные задачи
В `vercel.json` описаны две задачи на 06:00 UTC (09:00 МСК), но на Beget
этот файл не работает. **Нужен системный cron на сервере:**

```cron
# Москва, 09:00 — сводка за сутки и напоминания «пора связаться» в MAX
0 9 * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://module-estet.ru/api/cron/digest
2 9 * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://module-estet.ru/api/cron/reminders
```

Если часовой пояс сервера UTC — ставить `0 6` и `2 6`. Повторный запуск
в тот же день напоминания не дублирует.

| Адрес | Что |
|---|---|
| `/` | Главная: первый экран с главами, квиз-баннер, услуги, галерея, шкафы, сборка, материалы, наполнение, преимущества, «Как мы работаем», вопросы, призыв |

| `/privacy` | Политика конфиденциальности |
| `/vizkit` | **Скрытая** демо-страница ИИ-визуализатора: нет в меню и карте сайта, закрыта от поисковиков (`noindex`) |

При первом заходе играет заставка «Замер и проект» (`components/site-preloader.tsx`).
Повторно не чаще раза в 12 часов. Показать ещё раз: добавить `?preloader`
к адресу. В админке заставки нет.

Цена «Кухни от 90 000 ₽» — одна константа `kitchenPriceFrom` в
`lib/company.ts`. Там же срок изготовления `productionTime` (14 дней: вопросы
на главной и строка «Изготовление» во всех карточках портфолио), телефон,
часы работы и реквизиты.

## 6. Админка `/admin`

Вход по паролю (`ADMIN_PASSWORD_HASH`). Разделы:

- **Заявки** — список, карточка, смена статуса, **удаление** (вместе с файлами).
- **Клиенты** — все обращения по номеру телефона.
- **Календарь** — замеры по дням; замер можно **удалить** прямо из карточки.
- **Аналитика** — динамика за 60 дней, воронка квиза (по шагам кухонного
  квиза), воронка по статусам, источники, бюджеты, стили, планировки,
  сроки, причины отказов.
- **Каталог** и **Портфолио** — добавление и правка, загрузка фото.
  Проект, добавленный в `lib/portfolio-data.ts` после переноса портфолио
  в панель, на сайт сам не попадает: в разделе «Портфолио» он появится
  в блоке «Есть в коде сайта, но нет здесь» с кнопкой «Добавить».
  Пока раздел «Фасады» или «Столешницы» в панели пуст (или база не
  ответила при сборке), страница показывает черновик из каталога
  производства: 6 коллекций фасадов и 23 декора SLOTEX с фото
  (`lib/catalog-seed.ts`). Как только в разделе есть позиции, страница
  собирается из панели; раз в час она пересобирается сама.
- **Настройки** — проверка конфигурации, слоты замеров, уведомления MAX,
  «кто писал боту», состояние переменных окружения.
- **Экспорт** — заявки в CSV для Excel (`;`, с BOM).

Рабочие удобства панели (движение и где лежит код — [MOTION.md](./MOTION.md), раздел 9):

- **Быстрая правка** — карандаш в строке списка заявок и в списках дашборда
  (на телефоне — кнопка «Изменить» на карточке). Открывает панель сбоку:
  статус в одно нажатие (для отказа — причина), имя, телефон и адрес замера,
  ответственный, напоминание («Через 2 часа», «Завтра в 10», «Через 3 дня»),
  сумма, заметка. Всё пишется в историю заявки, правка контактов — с прежними
  значениями.
- **Поиск** — ⌘K / Ctrl+K или «/» на компьютере, лупа в шапке на телефоне:
  заявки по телефону, имени или номеру и переход в любой раздел.
- **Новые заявки** — счётчик на вкладке «Заявки» (красный, если есть
  просроченные), уведомление «Новая заявка» с кнопкой «Открыть», вибрация
  на Android и число на иконке приложения на телефоне. Панель сверяется
  с сервером раз в 45 секунд, пока открыта.
- **Тёмная тема** — переключатель внизу бокового меню и в листе «Ещё».
- Удаление подтверждается своим окном; после сохранения — короткое
  уведомление «Сохранено».

### Личный кабинет клиента `/kabinet`

Клиент видит свои заказы: этап (те же пять, что на сайте, и «Готово»),
полосу производства «прошло N из 14 дней», ближайшие визиты с кнопками
«В календарь» и «Перенести», проект — визуализации, спецификацию и кнопки
«Согласовать» / «Есть правки», документы, фотоотчёт, ленту событий,
своего менеджера и форму вопроса. Оплат в кабинете нет.

**Регистрации нет — кабинет открывает администратор.** Раздел «Кабинеты»
в панели или кнопка «Открыть кабинет» в карточке заявки (имя и телефон
подставятся, заказ по заявке создастся сам). Доступ — на выбор:

- **ссылка-приглашение** — клиент сам задаёт пароль, ссылка одноразовая,
  действует 7 дней;
- **пароль от администратора** — свой или сгенерированный вида
  «Fasad-4821»; запасной вариант, если клиенту неудобно со ссылкой.

Панель сразу показывает готовое сообщение клиенту с кнопками
«Скопировать» и «Отправить» (на телефоне — через MAX, WhatsApp, SMS).
Пароль и ссылка показываются один раз: в базе только хеши, потом можно
лишь выдать новые.

**MAX.** В том же сообщении — ссылка `https://max.ru/<бот>?start=…`:
клиент нажимает «Начать», и бот привязывает его MAX к кабинету. Если
ссылка не открылась — в «Профиле» кабинета есть код вида `ME-7KQ4FZ`,
его отправляют боту сообщением. После привязки:

- вход кодом из 6 цифр, который присылает бот, или кнопкой «Войти»
  прямо в сообщении (одноразовая, 10 минут);
- новости по заказу: этап, визит, проект на согласование, новые
  документы и фото, сообщения менеджера. В панели у каждого действия —
  галочка «Сообщить клиенту в MAX».

Ответы клиента (согласовал, правки, просьба перенести визит, вопрос)
приходят менеджерам в MAX — тем же, кто получает заявки
(`MAX_NOTIFY_USER_ID`), — с кнопкой «Открыть в панели».

**Защита.** Вход ограничен: 5 неверных паролей с адреса за 15 минут,
3 кода на номер за 10 минут, 5 попыток на один код. Форма входа
отвечает одинаково, есть номер в базе или нет. Файлы заказа отдаются
через `/kabinet/file/…` только владельцу заказа и только отмеченные
видимыми. Смена пароля, блокировка и «Выйти на всех устройствах»
обесценивают все выданные куки. Код — `app/kabinet`, `lib/cabinet-*.ts`,
`app/admin/cabinet-actions.ts`; таблицы `clients`, `client_tokens`,
`orders`, `order_visits`, `order_files`, `order_feed` создаются сами.

## 9. Правила для того, кто продолжит

- Тексты на сайте — только правдивые: цифры и обещания берутся из
  существующих текстов или от владельца. Пример: штамп «Ждёт подтверждения»
  на записи — потому что время закрепляется только после звонка.
- Не трогать рабочие заявки в базе при тестах; отправку форм в тестах
  перехватывать (так делает `tools/motion/render-thanks.cjs`).
- `.env.local` не коммитить, пароли в документы не писать.
- Анимации — по правилам из [MOTION.md](./MOTION.md): только `transform`
  и `opacity`, не ниже 45 fps на телефоне.
