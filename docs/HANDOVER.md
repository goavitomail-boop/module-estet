# Передача проекта «Модуль Эстет»

Сайт кухонь и шкафов на заказ: https://module-estet.ru. Документ для того,
кто принимает проект: где что лежит, как выкатывать, какие сервисы
подключены, что сделано и что осталось.

Секретов здесь нет и быть не должно: пароли и токены живут только
в `.env.local` на сервере. Ниже — названия переменных и зачем они нужны.

Моушн-дизайн (анимации, сцены, инструменты записи видео) описан отдельно:
[MOTION.md](./MOTION.md).

---

## 1. Коротко о проекте

| | |
|---|---|
| Стек | Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript |
| Пакетный менеджер | pnpm 10 (`packageManager` в `package.json`) |
| База данных | Postgres (Neon), драйвер `@neondatabase/serverless` |
| Файлы | Neon Object Storage, **приватный** бакет `files` (`lib/storage.ts`): заявки, планировки, фото квартир, портфолио, каталог. Vercel Blob — запасной на время переезда |
| Уведомления | Бот в мессенджере MAX |
| Аналитика | Яндекс.Метрика, счётчик **113551158** |
| Хостинг | Собственный облачный сервер Beget (не Vercel) |
| Репозиторий | `goavitomail-boop/module-estet`, рабочая ветка `claude/ecstatic-pasteur-gr53pi` |

Сайт запускается командой `next start` после `next build` (`pnpm build`,
`pnpm start`). Конфиг Next — `next.config.mjs`.

## 2. Выкатка на сервер

Сайт лежит в `/var/www/html`. Рядом — `/var/www/html-old`: в неё собирается
новая версия, пока старая продолжает работать. Затем папки меняются местами.

### Порядок

1. **Скачать код ветки** архивом:
   `https://github.com/goavitomail-boop/module-estet/archive/refs/heads/claude/ecstatic-pasteur-gr53pi.zip`.
   Внутри одна папка — закидывать её **содержимое**.
2. **Очистить `/var/www/html-old`** и распаковать туда файлы.
3. **Скопировать `.env.local`** из `/var/www/html` в `/var/www/html-old`.
   В архиве этого файла нет. Без него сайт соберётся, но заявки, админка
   и уведомления работать не будут.
4. **Собрать** (по SSH), старый сайт в это время работает:
   ```bash
   cd /var/www/html-old
   pnpm install
   pnpm build
   ```
   Ошибка в конце вывода — дальше не идти: рабочий сайт не затронут.
5. **Поменять папки местами:**
   ```bash
   cd /var/www
   mv html html-tmp && mv html-old html && mv html-tmp html-old
   ```
6. **Перезапустить сайт.** Он работает под pm2, процесс `nextjs-app`:
   ```bash
   pm2 restart nextjs-app
   pm2 save
   ```
   Список процессов и их состояние — `pm2 list`, журнал сайта — `pm2 logs nextjs-app`.
7. **Проверить** главную, `/quiz`, `/admin`.

### Откат

Повторить шаг 5 (папки снова поменяются) и перезапустить. Предыдущая
версия лежит в `html-old` до следующей выкатки.

### Локально

- Windows: `start-local.bat` — ставит зависимости, собирает и запускает.
- Любая система: `pnpm install`, затем `pnpm dev` (разработка) или
  `pnpm build && pnpm start`. Сайт на http://localhost:3000.
- Без `.env.local` сайт открывается, но заявки не сохраняются.

## 3. Переменные окружения

Файл `.env.local` в корне проекта, на сервере — в `/var/www/html`. Образец
с подробными пояснениями — `.env.example`. **Никогда не коммитить**
`.env.local` (он в `.gitignore`).

| Переменная | Зачем | Обязательна |
|---|---|---|
| `DATABASE_URL` | Postgres. Также читаются `POSTGRES_URL`, `DATABASE_URL_UNPOOLED`, `POSTGRES_URL_NON_POOLING` | да — без неё заявки не сохраняются |
| `AWS_ENDPOINT_URL_S3`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` | Neon Object Storage — бакет `files` для всех файлов сайта. Ключ: `neon credentials create --scope storage:read --scope storage:write` на ветке production | да — без них файлы пишутся в Vercel Blob |
| `STORAGE_BUCKET`, `STORAGE_CORS_ORIGINS` | Другое имя бакета; ещё адреса для загрузки из браузера (сайт и www разрешены всегда) | нет |
| `BLOB_READ_WRITE_TOKEN` | Старое хранилище Vercel Blob: читать файлы, ещё не перенесённые в Neon | пока не выполнен перенос |
| `BLOB_STORE_ID` | Идентификатор хранилища Vercel Blob | по ситуации |
| `ADMIN_PASSWORD_HASH` | Пароль админки в виде `scrypt:соль:хеш`. Команда генерации — в `.env.example` | да |
| `ADMIN_PASSWORD` | Устаревший пароль открытым текстом. Панель помечает его как небезопасный | нет — лучше перейти на хеш |
| `ADMIN_SESSION_SECRET` | Подпись сессионной куки, 32+ случайных символа | желательно |
| `MAX_BOT_TOKEN` | Токен бота MAX | да — для уведомлений |
| `MAX_NOTIFY_USER_ID` | Кому слать заявки. **Несколько получателей — через запятую**: `12345,67890` | да |
| `MAX_NOTIFY_CHAT_ID` | Групповой чат или канал для дубля заявок | нет |
| `MAX_WEBHOOK_SECRET` | Проверка входящих событий бота (`/api/max-webhook`) | желательно |
| `MAX_DIAG_KEY` | Ключ к диагностике `/api/max-diag` (без него — 404) | нет |
| `MAX_API_BASE`, `MAX_STRICT_TLS` | Адрес API MAX и строгая проверка TLS | нет |
| `CRON_SECRET` | Защита регулярных задач `/api/cron/*` | да, если задачи открыты в интернет |
| `MEASUREMENT_SLOT_CAPACITY` | Сколько замеров в один слот (утро/день/вечер), по умолчанию 1 | нет |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | Номер счётчика. По умолчанию 113551158 | нет |
| `NEXT_PUBLIC_MAX_CHAT_URL` | Ссылка «Написать в Max» | нет |
| `NEXT_PUBLIC_YANDEX_VERIFICATION`, `NEXT_PUBLIC_GOOGLE_VERIFICATION` | Подтверждение прав в вебмастерах | нет |

После изменения `.env.local` сайт нужно перезапустить. Переменные
`NEXT_PUBLIC_*` попадают в код при сборке — после их смены нужна пересборка.

## 4. Подключённые сервисы

### База и файлы
- Заявки, сессии квиза, замеры, каталог и портфолио — в Postgres
  (`lib/db.ts`).
- Файлы — в приватном бакете `files` Neon Object Storage (`lib/storage.ts`,
  бакет объявлен в `neon.ts`). Посетителю фото портфолио и каталога отдаёт
  `/media/...` (там белый список папок), админке — `/admin/file`. Браузер
  грузит файлы прямо в бакет по подписанной ссылке, запасной путь — через
  сервер (`PUT /api/upload`, `PUT /admin/upload`).
- Vercel Blob — запасной: пока переменных `AWS_*` нет, файлы пишутся туда;
  когда есть, сайт читает сначала Neon, потом Blob, поэтому ещё не
  перенесённые файлы открываются.

### Переезд файлов в Neon — один раз
1. Проверить регион проекта Neon: Object Storage есть в `aws-us-east-1`,
   `aws-us-east-2`, `aws-eu-central-1`, `aws-ap-southeast-1` (регион
   печатает проверка в GitHub Actions, задача «Neon — ветка базы»).
2. Создать бакет на production: `neon deploy` на ветке production (бакет
   объявлен в `neon.ts`) или в консоли Neon → ветка production → Object
   storage → New bucket `files`, доступ private.
3. Ключ для сервера: `neon credentials create --scope storage:read --scope storage:write --name module-estet-site`
   (на ветке production) или консоль → Settings → Credentials. Секрет
   показывается один раз — сразу в `.env.local` на сервере вместе с
   `AWS_ENDPOINT_URL_S3` и `AWS_REGION`. Никому не пересылать.
4. На сервере: `node --env-file=.env.local scripts/neon-storage.mjs setup` —
   CORS бакета (загрузка из браузера), затем перезапуск сайта.
5. Перенос старых файлов: `node --env-file=.env.local scripts/neon-storage.mjs migrate --dry-run`,
   потом без `--dry-run` (нужен ещё `BLOB_READ_WRITE_TOKEN`). Повторный
   запуск пропускает уже перенесённые. Проверка: `... neon-storage.mjs check`.
6. После переноса `BLOB_READ_WRITE_TOKEN` можно убрать, а хранилище Vercel
   Blob удалить не раньше, чем убедитесь, что старые заявки открываются.
7. Если перед сайтом nginx: `client_max_body_size 30m;` — иначе запасной
   путь загрузки через сервер отсечёт файлы больше 1 МБ.

### Бот MAX
- Новая заявка уходит всем из `MAX_NOTIFY_USER_ID` (`lib/max-bot.ts`,
  `lib/max-ui.ts`).
- В боте есть меню: списки заявок, фильтры, карточка заявки, статистика
  (`/api/max-webhook`).
- Настоящий `user_id` получателя виден только после того, как он открыл
  бота и написал ему. Узнать: `/api/max-diag?key=<MAX_DIAG_KEY>`, поле
  `incomingSenders`. Кто писал боту — также в `/admin/settings`.
- `/call?phone=...` — страница-переход на звонок из кнопки в MAX.

### Яндекс.Метрика
- Счётчик 113551158 (`lib/metrika.ts`, `components/yandex-metrika.tsx`).
- Загружается сразу. Если посетитель выбрал «только необходимые»
  cookie, счётчик выключается (`lib/consent.ts`).
- Цели, которые отправляет сайт. **Их нужно один раз завести в интерфейсе
  Метрики** («JavaScript-событие» с тем же идентификатором):

  | Идентификатор | Когда |
  |---|---|
  | `lead_measurement` | отправлена заявка на замер |
  | `lead_project` | отправлен квиз кухни |
  | `lead_wardrobe` | отправлен квиз шкафа |
  | `click_phone` | клик по номеру телефона |
  | `click_max` | клик по ссылке на MAX |

### Регулярные задачи
В `vercel.json` описаны две задачи на 06:00 UTC (09:00 МСК), но на Beget
этот файл не работает. **Нужен системный cron на сервере:**

```cron
# Москва, 09:00 — сводка за сутки и напоминания «пора связаться» в MAX
0 9 * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://module-estet.ru/api/cron/digest
2 9 * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://module-estet.ru/api/cron/reminders
```

Если часовой пояс сервера UTC — ставить `0 6` и `2 6`. Повторный запуск
в тот же день напоминания не дублирует.

## 6. Админка `/admin`

Вход по паролю (`ADMIN_PASSWORD_HASH`). Разделы:

- **Заявки** — список, карточка, смена статуса, **удаление** (вместе с файлами).
- **Клиенты** — все обращения по номеру телефона.
- **Календарь** — замеры по дням; замер можно **удалить** прямо из карточки.
- **Аналитика** — динамика за 60 дней, воронка квиза (по шагам кухонного
  квиза), воронка по статусам, источники, бюджеты, стили, планировки,
  сроки, причины отказов.
- **Каталог** и **Портфолио** — добавление и правка, загрузка фото.
  Пока раздел «Фасады» или «Столешницы» в панели пуст (или база не
  ответила при сборке), страница показывает черновик из каталога
  производства: 6 коллекций фасадов и 23 декора SLOTEX с фото
  (`lib/catalog-seed.ts`). Как только в разделе есть позиции, страница
  собирается из панели; раз в час она пересобирается сама.
- **Настройки** — проверка конфигурации, слоты замеров, уведомления MAX,
  «кто писал боту», состояние переменных окружения.
- **Экспорт** — заявки в CSV для Excel (`;`, с BOM).

   открытая модель на арендованном GPU, в том числе в российском облаке
   (например Qwen-Image-Edit, лицензия Apache 2.0), или зарубежный провайдер,
   если есть законная возможность им платить.
2. **Стенд на 1–2 дня:** прогнать 15–20 реальных фото «до» через 2–3 модели
   одним промтом и выбрать.
3. **Встраивание:** заменить заглушку в `components/vizkit.tsx` на вызов
   своего API-маршрута. Промт уже собирается из выбора, референсы пронумерованы.
4. **Обязательно:** лимит генераций на номер или IP и капча; согласие
   на обработку фото и срок их хранения; при отправке за рубеж —
   трансграничная передача в политике конфиденциальности; подпись
   «визуализация примерная».

## 9. Правила для того, кто продолжит

- Тексты на сайте — только правдивые: цифры и обещания берутся из
  существующих текстов или от владельца. Пример: штамп «Ждёт подтверждения»
  на записи — потому что время закрепляется только после звонка.
- Не трогать рабочие заявки в базе при тестах; отправку форм в тестах
  перехватывать (так делает `tools/motion/render-thanks.cjs`).
- `.env.local` не коммитить, пароли в документы не писать.
- Анимации — по правилам из [MOTION.md](./MOTION.md): только `transform`
  и `opacity`, не ниже 45 fps на телефоне.
