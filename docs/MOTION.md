Как устроены анимации сайта, по каким правилам делать новые и как их
проверять. Общие сведения о проекте — в [HANDOVER.md](./HANDOVER.md).

---

## 1. Принципы

Стиль: тёмная сцена, латунные акценты, сдержанная премиальность. Движение
объясняет, а не украшает: процесс, результат, снятие сомнения.

1. **Одна главная анимация на экран.** Если два объекта спорят за внимание,
   один ждёт.
2. **Сцены перетекают, а не обрываются.** Переход мотивирован объектом:
   выбранная карточка улетает в плашку «Ваш выбор», корпус телефона тает
   и снимок становится кадром, створки-купе открывают шкаф. Пустых кадров
   между сценами нет: следующая входит, пока уходит предыдущая.
3. **Уход вдвое короче входа и разгоняется.** Вход 0,6–0,95 с с пружиной,
   уход 0,25–0,35 с с ускорением: уходящее не держит взгляд.
4. **Пружины, а не «резинка».** Перелёт около 1 % для крупного, до 8 % для
   значков. Мультяшного подпрыгивания нет.
5. **Текст стоит, пока его читают.** На фразу — не меньше секунды плюс
   примерно 0,25 с на каждое слово сверх трёх. Заголовки выезжают из-под
   маски по словам или строкам, потом не двигаются.
6. **Палец показывает, где нажимать** — касание, нажатие, кольцо. Человек
   сразу понимает, что от него ждут.
7. **Только правда.** Все надписи в сценах — с сайта или от владельца:
   формулировки квиза, слоты замера, ответ после заявки, цена «от 90 000 ₽».
8. **Не мешать.** Автопоказ дольше 5 секунд — с кнопкой паузы; ушедшая
   с экрана сцена стоит; «уменьшить движение» в системе — всё сразу
   на месте.
9. **60 кадров.** Цель 60 fps, допустимо не ниже 45 на телефоне
   (см. раздел 6).

Где движение **не нужно**: поля форм, вопросы и ответы, подвал, админка.

## 2. Токены

Заданы на корне сцены `.hs` (`components/scene-kit.css`). Ролик визуализатора
`/vizkit` использует те же значения на корне `.vzi`, створки квиза — свои
`--qd-*`.

| Переменная | Значение | Для чего |
|---|---|---|
| `--out` | `cubic-bezier(0.16, 1, 0.3, 1)` | приход, появление, текст |
| `--in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | перемещение между состояниями: шторка, створки, палец |
| `--leave` | `cubic-bezier(0.55, 0, 0.75, 0)` | уход |
| `--spring` | `linear(…)`, затухание 0,82, перелёт ~1 % | карточки, панели, сцены |
| `--pop` | `linear(…)`, затухание 0,62, перелёт ~8 % | значки, плашки, штампы |

`linear()` с точками пружины работает в Chrome 113+, Safari 17.2+, Firefox 112+.
В старых браузерах — запасные `cubic-bezier` через `@supports`.

| Что | Сколько |
|---|---|
| Вход слоя | 0,6–0,95 с |
| Уход слоя | 0,25–0,35 с |
| Шторка между сценами | 1,0 с |
| Створки-купе | 1,45 с |
| Шаг очереди: слова / плашки / строки / шаги | 0,06 / 0,07–0,16 / 0,14 / 0,25 с |
| Глава первого экрана | 4,8–5,6 с |

## 3. Набор `scene-kit`

`components/scene-kit.tsx` и `components/scene-kit.css`. Корень сцены —
класс **`hs`**, на нём кривые. Всё, что ниже, работает только внутри `.hs`.

### Как задаётся время

Каждый слой получает переменные в `style`. Помощники ставят их **все сразу**:
CSS-переменные наследуются, и забытая переменная взялась бы у родителя.

```tsx
import { enter, leave, POP, Finger } from '@/components/scene-kit'

<div className="hs-in" style={enter(0.6)} />                      // появится на 0,6 с
<div className="hs-in" style={enter(1.2, POP)} />                   // значок с пружинкой
<div className="hs-in" style={enter(0.4, { t: 0.9, from: 'translateY(40%)' })} />
<div className="hs-out" style={leave(3.1)}>…</div>                  // уйдёт на 3,1 с
```

- `enter(d, { t, from, ease })` → `--d` задержка, `--t` длительность,
  `--from` начальный `transform`, `--e` кривая (по умолчанию `var(--spring)`).
- `leave(od, { t, to })` → `--od`, `--ot`, `--to`.

### Классы

| Класс | Что делает |
|---|---|
| `hs-in` | проявляется из `--from` |
| `hs-out` | уходит в `--to` в момент `--od`; до него не действует |
| `hs-leave` | вся сцена гаснет сразу (уходящая глава) |
| `hs-mask` | строка выезжает из-под маски: `<span class="hs-mask"><span style="--d:…">Текст</span></span>` |
| `hs-fade` | только проявление, без сдвига (смена фото поверх фото) |
| `hs-wipe` + дочерний `hs-wipe-img` | шторка справа налево: слой едет, содержимое стоит; `hs-wipe--back` — слева направо |
| `hs-draw-x`, `hs-draw-y` | линия прочерчивается; `--origin` — откуда растёт |
| `hs-press` | короткое нажатие кнопки в момент `--d`; `--press` — насколько вдавливается (по умолчанию 0,8, широкой кнопке 0,96) |
| `hs-tick` | галочка прочерчивается (у пути `pathLength={1}`) |
| `hs-finger` (компонент `Finger`) | палец: прилетает, нажимает, уходит |

**Палец живёт внутри цели**, а не в общих координатах:

```tsx
<span className="relative …">Угловая
  <Finger d={1} tap={1.55} out={2} to="translate(160%, 40%)" />
</span>
```

Так он попадает в кнопку на любом экране. Переход «от одной кнопки
к другой» — два пальца: первый уходит в сторону второй (`to`), второй
прилетает оттуда (`from`).

**Штамп** — `hs-in` с `from: 'scale(1.9)'` и кривой `--pop`, а постоянный
наклон — классом Tailwind (`-rotate-12`). Классы `rotate`/`translate`/`scale`
в Tailwind 4 — отдельные CSS-свойства и складываются с анимацией `transform`.

### Сцена ниже первого экрана: `PlayWhenSeen`

`components/play-when-seen.tsx` — корень сцены (`hs`), который держит все
её CSS-анимации на первом кадре, пока блок не войдёт в экран (и пока идёт
заставка), а потом отпускает один раз. Время слоёв внутри считается
от этого момента. При «уменьшить движение» и без JavaScript не ждёт.

```tsx
<PlayWhenSeen className="…">
  <div className="hs-in" style={enter(0.3)}>…</div>
</PlayWhenSeen>
```

### Экраны «спасибо»: `components/thanks-scene.tsx`

- `CheckBadge` — латунный кружок выпрыгивает, галочка прочерчивается.
- `SummaryCard` — карточка, в которую по одной влетают строки, сверху штамп.
- `NextSteps` — «Что дальше»: линия прочерчивается, шаги встают по очереди
  (`tone="dark"` или `"light"`).

### Первый экран: как добавить главу

1. Написать сцену — функцию, которая возвращает слои с `enter(…)`. Время
   считается **от начала главы**.
2. Добавить объект в `CHAPTERS`: `tab`, `title`, `text`, `link`,
   `bg` (фото), `enter: 'wipe' | 'doors'`, `dim` (затемнить фото под
   интерфейс), `dur`, `Scene`.
3. `dur` = момент последней анимации + 1–1,5 с, чтобы результат успели
   прочитать.
4. Все фоны лежат в DOM всегда (`invisible`), поэтому фото следующей главы
   уже загружено к её началу.

### «Как мы работаем»: как добавить или поменять шаг

Объект в массиве `steps`: `number`, `title`, `description`, `Scene`. Сцена
монтируется, когда шаг становится текущим, и отыгрывает с нуля. Высота
блоков шагов (`min-h-[44svh]`, на компьютере `lg:min-h-[64vh]`) задаёт,
сколько надо прокрутить до следующего.

### Ролик визуализатора

Время меняется только в `TL` в начале `vizkit-intro.tsx`. Сдвиг одного
события двигает и путь пальца, и шторку. `SEAM` и `FINGER` — опорные точки
путей. После конца ролика шторка переходит в ручной режим (`vzi-live`).

## 5. Рецепт новой сцены

```tsx
import { enter, leave, POP } from '@/components/scene-kit'

<div className="hs relative aspect-[4/3] overflow-hidden rounded-3xl border border-primary/30 bg-[#161412] text-background">
  {/* фон */}
  <Image src="…" alt="" fill className="object-cover" />
  {/* плашка: вход и уход — на РАЗНЫХ элементах */}
  <div className="hs-out absolute left-[4%] top-[5%]" style={leave(3.2)}>
    <span className="hs-in block rounded-full bg-primary px-3 py-1" style={enter(0.6, POP)}>Новое</span>
  </div>
  {/* заголовок из-под маски */}
  <p className="flyer-title"><span className="hs-mask"><span style={{ '--d': '0.3s' } as CSSProperties}>Заголовок</span></span></p>
</div>
```

Схемы в аксонометрии («Наполнение», шкаф, размеры шкафа, модуль в разрезе) строятся на `components/axo.ts`: точка
в миллиметрах → точка чертежа, грани, сдвиг «к зрителю» для выдвижного, обрезка
по проёму. Ракурс у каждой схемы свой (`axonometry(оси, глубина)`): кухню видно
скорее сбоку, шкаф — почти спереди, чтобы секции читались целиком (`wardrobeView`,
общий для «Что внутри шкафа» и «Размеров»), модуль кухни в разрезе — спереди-справа с длинной
глубиной (`moduleView`).

Смена сцен шторкой: контейнер новой сцены с `hs-wipe`, внутри — обёртка
`hs-wipe-img` со всем содержимым. Старая сцена лежит под ней, пока шторка
не дошла, затем убирается (`onAnimationEnd`). Готовые примеры —
`hero-showcase.tsx` и `process-section.tsx`.

## 6. Производительность

### Правила
- Анимировать **только `transform` и `opacity`**. Никогда: `filter`, `blur`,
  `backdrop-filter`, `mix-blend-mode`, `letter-spacing`, `left/top/width/height`,
  `box-shadow`.
- Тени, градиенты, сетки — статичные; движется слой целиком.
- `will-change` — только у створок, которые поворачиваются в 3D.
- В 3D: перспектива на **прямом** родителе; внутри поворачивающейся створки
  во время поворота ничего не анимировать.
- Слой размером со сцену анимируется **только в своё окно** (задержка
  и `forwards`). Если он «анимируется» весь ролик, даже стоя на месте,
  без видеокарты перерисовывается весь кадр.
- Маленький подвижный объект — маленький слой. Палец в ролике `/vizkit`
  двигается в единицах контейнера (`cqw`), а не как слой на всю сцену.
- Анимируется только текущая сцена; ушедшие с экрана стоят.

### Ловушки, на которые уже наступили
| Симптом | Причина → что сделать |
|---|---|
| На телефоне при прокрутке карточки растут и сжимаются | высоты в `dvh` меняются вместе с адресной строкой → **`svh`** |
| Верх окна обрезан и не прокручивается | `justify-center` при переполнении → **`justify-center-safe`** |
| Кольцо или пульс видно до своего момента | заполнение `both` показывает первый кадр заранее → `forwards` и `opacity-0` на элементе |
| Вход и уход на одном элементе не работают вместе | два класса с `animation` перебивают друг друга → внешний элемент уходит, внутренний входит |
| Слой взял чужую задержку | CSS-переменные наследуются → ставить все через `enter()`/`leave()` |
| Первая секция страницы через пару секунд темнеет или замирает (так было с выбором в квизе) | глобальное `hero-reveal` в `globals.css` с `fill: both` закрепляет начальный кадр → атрибут `data-own-motion` на секции со своей анимацией |
| Две картинки разного масштаба при переходе | «общий объект» должен совпадать: снимок в телефоне размером со сцену и по её центру |
| Палец не виден | белый на белой кнопке → тёмная заливка с белым кантом |
| Под шторкой в просмотре фото на миг темнеет | просмотр проявляет фото за 0,25 с → шторку убирать, когда у фото непрозрачность 1 и нет анимаций |
| Подпись на SVG-чертеже не повернулась | атрибут `transform` у элемента SVG перебивает CSS-анимация `transform` (`hs-in`) → поворот на обёртке `<g>`, анимация на вложенном элементе. Масштаб и появление по своей рамке — `transform-box: fill-box` |
| `ReferenceError` на импортированной функции, только в собранном сайте | `await` в третьей части `for (…; …; await f())` сборщик не связывает с импортом → `await` в теле цикла |

### Замер
`tools/motion/fps.cjs` (раздел 7). В контейнере без видеокарты при последней
проверке:

| Что | Компьютер | Телефон |
|---|---|---|
| Первый экран, полный круг | 55–60 | 60 |
| «Как мы работаем», прокрутка | 49–60 | 60 |
| Ролик `/vizkit` | 43–60 | 60 |

На реальных устройствах с видеокартой выше. Сравнивайте версии **между собой
в одних условиях**, а не с идеалом.

## 7. Проверка и запись видео

Инструменты в `tools/motion/`. Нужны Node 20+, ffmpeg и Playwright
с Chromium:

```bash
npm i -g playwright && npx playwright install chromium
export NODE_PATH="$(npm root -g)"     # чтобы скрипты нашли playwright
pnpm build && pnpm start              # сайт на http://localhost:3000
```

Другой адрес — переменная `BASE_URL`.

**Главный приём — виртуальные часы.** Все CSS-анимации стоят на паузе,
и каждый кадр скрипт сам сдвигает их на 1/60 секунды. Видео выходит ровно
60 fps даже там, где запись «вживую» дёргается. Дошедшие до конца анимации
завершаются по-настоящему, поэтому работают смены глав по `animationend`.

| Скрипт | Для чего | Пример |
|---|---|---|
| `render-timeline.cjs` | всё, что идёт само: первый экран, `/vizkit`, створки | `node tools/motion/render-timeline.cjs / out/hero.mp4 --secs 27` |
| | отдельные кадры | `node tools/motion/render-timeline.cjs /quiz out/frames --stills 1,2.6,3.4` |
| `render-scroll.cjs` | «Как мы работаем»: сам листает к каждому шагу | `node tools/motion/render-scroll.cjs / out/process.mp4 --mobile` |
| | «Монтаж»: `--imgs` — какие фото ждать на каждом кадре (скрытые на этом экране не загрузятся, и запись будет ждать их впустую) | `node tools/motion/render-scroll.cjs / out/assembly.mp4 --section '#assembly' --hold 2.3 --imgs '#assembly .sticky img'` |
| `render-thanks.cjs` | экраны «спасибо»; отправка формы перехвачена, заявок не создаёт | `node tools/motion/render-thanks.cjs booking out/thanks.mp4` |
| `fps.cjs` | плавность вживую, по секундам | `node tools/motion/fps.cjs / --secs 26` · `--scroll '#process'` |

У всех: `--mobile` (390×844, касания), `--w`, `--h`.

### Посмотреть результат глазами
```bash
# раскадровка: кадр в секунду, плиткой
ffmpeg -i out/hero.mp4 -vf "fps=1,scale=320:-1,tile=6x5" -frames:v 1 out/contact.png
# 12 кадров вокруг быстрого перехода
ffmpeg -ss 5.1 -i out/hero.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 out/strip.png
```

### Чек-лист перед выкаткой
- [ ] В каждом кадре один главный объект, ничего не наезжает
- [ ] Нет пустых кадров между сценами
- [ ] Уходы быстрее входов, ничего не движется линейно, кроме полосок прогресса
- [ ] Текст стоит, пока читается; читается на ширине телефона
- [ ] Палец виден на любой кнопке
- [ ] «Уменьшить движение» в системе — всё сразу на месте, ничего не листается само
- [ ] Ушедшая с экрана сцена стоит; есть пауза, если автопоказ дольше 5 с
- [ ] `fps.cjs`: на телефоне не ниже 45
- [ ] Все надписи правдивы
